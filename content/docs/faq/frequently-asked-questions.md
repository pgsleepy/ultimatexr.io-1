# UltimateXR FAQ

## Is UltimateXR actively developed?

Yes. UltimateXR is actively used and developed at VRMADA as part of our own projects. Many improvements come directly from real production needs.

## Why is the GitHub repository not updated daily or weekly?

UltimateXR is developed internally at VRMADA using a private PlasticSCM repository. GitHub is used as the public distribution channel, so updates are pushed there when they contain meaningful improvements, fixes, or release-ready changes.

That said, we are changing the way we publish updates. From now on, we plan to push changes to GitHub much more frequently, making it easier for the community to follow progress and access recent improvements.

## Why is development done internally first?

UltimateXR is part of VRMADA’s production workflow, so new features are usually developed, tested, and refined inside real projects before they are prepared for public release. This helps ensure that what reaches GitHub is useful, stable, and tested in practical scenarios.

## Does UltimateXR have a public roadmap?

We want to make development more transparent going forward. A public roadmap, backlog, and WIP updates are going to be available soon.

## Can I use UltimateXR in commercial projects?

Yes. UltimateXR is released under the MIT License, so it can be used in real VR applications, including commercial and enterprise projects. You can use, modify, and distribute it according to the terms of the MIT License.

## Is UltimateXR only for programmers?

No. UltimateXR includes many systems that can be configured directly in Unity, without writing code. Designers and technical artists can use prefabs, components, inspectors, and scene setup tools to build prototypes and full VR applications.

Programmers can also extend and customize the framework to unlock its full potential.

## Is UltimateXR tied to a specific headset or SDK?

No. UltimateXR is designed to support multiple XR platforms. It now includes OpenXR support, which provides a common path for modern XR development, while still allowing native SDK integrations where needed.

## Why does UltimateXR include so many systems instead of focusing only on grabbing?

In production VR applications, grabbing is only one part of the experience. A complete framework also needs avatars, locomotion, UI interaction, hand poses, networking support, and many other systems.

UltimateXR aims to provide a complete framework with support for everything needed to build XR applications.

## Is UltimateXR suitable for enterprise VR training?

Yes. UltimateXR is based on years of experience developing enterprise VR training applications for governments and private organizations. Many of its systems are designed around practical training requirements.

## Can I contribute to UltimateXR?

Contributions, suggestions, and feedback are welcome. The best way to participate is through GitHub issues, discussions, or pull requests. You can also join our [Discord Server!](https://discord.gg/GXHdneaFjA).

## How stable is UltimateXR?

UltimateXR is used in production projects, but like any active framework, it continues to evolve. We try to keep public releases stable and useful, while continuing to improve the framework over time.

## Where should I report bugs or request features?

Please use the GitHub repository to report bugs, request features, or start discussions. Clear reproduction steps, Unity version, target platform, headset, and relevant logs are especially helpful when reporting issues.
